# 游戏陪伴宠物（LLM/VLM代理）需求草案（阶段1-2）

## 1. 项目目标

构建一个本地运行的游戏陪伴宠物代理，用于 RPG 游戏测试辅助。  
系统可由用户手动开启/关闭，在运行状态下执行以下闭环：

1. 截图与文本采集（感知）
2. LLM/VLM 决策（规划下一步动作）
3. 键鼠动作执行（输入）
4. 状态记录与异常回退（控制）

## 2. 阶段范围

### 阶段1：基础闭环（MVP）

目标：打通看-想-做最小链路，完成基础自动操作。

功能要求：

- 周期截图（默认 1-2 秒，可配置）
- OCR 文本提取（对话、按钮、任务提示）
- 可选日志输入（本地日志文件）
- LLM/VLM 输出标准动作指令（点击、按键、等待）
- 键盘/鼠标基础执行
- 启停控制与紧急停止
- 最近动作与识别结果展示

验收标准：

- 连续运行 10 分钟无崩溃
- 可完成基础流程（推进对话、确认菜单）
- 停止后 1 秒内不再发送输入

### 阶段2：RPG 可测增强

目标：在真实测试中可控可回退，降低卡死与误操作。

功能要求：

- 状态机：探索、对话、菜单、等待
- 短期记忆：最近 N 步动作、失败计数、当前目标
- 动作白名单和节流策略
- 重复动作熔断（超阈值自动暂停）
- 卡住检测（低画面变化 + 高重复动作 + 超时）
- 恢复策略（等待/返回/切换目标/暂停提示）
- 决策与执行日志可追溯
- 按游戏配置 OCR 区域与动作映射

验收标准：

- 可连续运行 30-60 分钟
- 卡住时可自动恢复或安全暂停
- 测试流程成功率达到预设目标（例如大于 70%）
- 全量日志可复盘误操作原因

## 3. 运行开关与状态标记（P0）

这是本项目第一优先级需求，必须先落地。

### 3.1 控制开关

- 主开关：开始/停止
- 紧急停止：全局热键（默认 Ctrl+Alt+S，可配置）
- 状态切换规则：
  - 开始：进入运行态并开启感知循环
  - 停止：立刻停止决策与输入执行
  - 急停：无条件中断动作队列并切换到已急停

### 3.2 状态可视化

必须让用户一眼识别当前状态：

- 运行中：绿色 + 脉冲标识
- 已停止：灰色
- 异常/暂停：橙色
- 文本状态：运行中/已停止/卡住恢复中/已急停
- 运行时长与最后动作时间显示

### 3.3 一致性约束

- UI 状态、内部状态机、执行器状态必须一致
- 执行器异常退出后，UI 在 1 秒内切换异常/停止
- 禁止出现 UI 显示已停止但仍输入的情况

## 4. 非功能要求（阶段1-2）

- 决策延迟控制在可用范围（目标 1-2 秒）
- 模型失败或超时时不崩溃，进入降级流程
- 默认只在用户显式开启后执行输入动作
- 默认拒绝白名单外动作

## 5. 范围外（阶段2不做）

- 高频实时战斗微操
- 多游戏全自动泛化
- 云端多用户系统
- 高复杂度宠物动画
